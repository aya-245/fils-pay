# Money / fees audit notes

Truth used: 1 BD = 1000 fils, integer fils (ADR-0001). CLAUDE.md claims (cents, frozen money package, "tests are locked") were ignored; `packages/money` itself was correct and is unchanged.

**MF-1 | High | apps/api/src/admin/adjustmentCsvParsing.ts:8, lib/decimal.ts | CSV import scales by 100.** `parseDecimalMinor(raw)` defaults to 2 decimals: it truncates 4.755 to 4.75 then reads it as 475 "fils"; "4.75" becomes 475 (0.475 BD, 10x too small); 4.755 BD loses its third digit. | Helper written for cents currencies. | Every imported adjustment posted to the ledger and balance cache. | Use `parseBhdToFils` (rejects more than 3 decimals). | moneyFees.new.test.ts bug1; adjustmentImport.test.ts assertions updated: totalPostedFils 600->6000, row amounts 475->4750 and 125->1250, negative legs 350->3500, balance cache 500->5000 (they encoded the 10x bug).

**MF-2 | High | apps/api/src/fees/currentFeeScheduleDisplay.ts:~35 | Display shows 245bps, charged 225bps.** Display orders by `created_at DESC` with no effective-date filter; charging (`getEffectiveMdrBps`) uses `effective_from <= asOf ORDER BY effective_from DESC, created_at DESC`. | A later-entered backfill or future-dated row wins on created_at. | Merchant and support see a rate that is not billed. | Same predicate and ordering as charging. | bug2; currentFeeScheduleDisplay.test.ts "backfilled later" assertion updated 245->225 and effectiveFrom/createdAt to the Aug row (it asserted the bug).

**MF-3 | High | scripts/reconcile_march.ts | Sweep not idempotent.** `entry_group_id` was `randomUUID()` each run; the comment claiming dedupe was wrong. | No natural key. | Second run doubled the residue write-off. | Deterministic group id per (period, merchant) from sha256, existence check, advisory xact lock. Second run is a no-op. (The sweep uses the UTC month per ADR-0003; HANDOVER says Bahrain month, left for finance to decide.) | bug3.

**MF-4 | Medium | scripts/lib/sqlFilter.ts, expire_holds.ts, reporting/transactionsReportQuery.ts, analytics/query.ts | Unsafe/slow filters.** (a) sqlFilter interpolated column and table names, and an empty filter produced an unfiltered `DELETE FROM holds` (an empty expired list wiped the table). expire_holds now does one guarded `UPDATE ... SET status='expired'` (holds are never deleted: HANDOVER/0005). sqlFilter validates identifiers and refuses an unfiltered DELETE. (b) The report query passed untyped strings, so bare dates meant session-timezone midnight, not the Bahrain day; now validated and converted to Bahrain instants (still bound parameters, index-friendly `occurred_at` range). (c) `getRecentLedgerActivity` wrapped `occurred_at` in `AT TIME ZONE ...::date BETWEEN` (no index use); now a half-open timestamptz range. | | | | bug4; expire_holds.test.ts rewritten (it asserted the DELETE text).

**MF-5 | Medium | transactions/exportCsv.ts, routes/transactions.ts, plugins/multipart.ts, onboarding/kycThumbnail.ts | Unbounded memory.** Export built the full result set and string; the existing paged streamer paged on `occurred_at > cursor` (JS Date, ms), dropping rows with equal timestamps. Now a keyset generator on (occurred_at text, id), and the route streams it. Multipart limits: files 1, fields 10, parts 12, fieldSize 10KB (file size cap already existed). sharp `limitInputPixels` 50MP. CSV escape also quotes `\r`. | | | | bug5 (1005 rows with the same timestamp).

**MF-6 | High | admin/merchantFlags.ts, transactionStatusRecompute.ts, bulkKyc.ts | Admin tools hit the wrong rows.** (a) Recompute scanned every status except authorized/voided, so `chargeback` rows were rewritten to captured/refunded; now only capture/refund family. (b) `reconcileSandboxFlag` flipped `test_mode` to false for any test merchant with transactions (open-authorization count was always 0): sandbox merchants silently went live; now a no-op. (c) Bulk KYC approved any id, including rejected ones, contradicting its docs; now `onboarding_status = 'under_review'` only. (d) `reportingRebuild` dropped refund_count/refund_gross_fils (0073); now rebuilt from succeeded `refunds`, bucketed on the Bahrain date. Rebuild does not filter test merchants: the live reporting consumer does not either. | | | | bug6, reportingRebuild.new.test.ts.

**MF-7 | High | db/migrations/0049 (fix: 0080_platform_stats_bigint.sql), fees/platformVolumeTier.ts | INT4 overflow.** `platform_stats.total_processed_fils` was INTEGER (max 2,147,483,647) against a 2,000,000,000 threshold; CloseBatch would error past 2,147,483.647 BD. Widened to BIGINT; pg returns BIGINT as text so the read uses `Number()`. creditThreshold (50_000 fils = 50.000 BD per ADMIN.md) is correct. | | | | bug7.

Not changed: ledger/credits/settlementClient/dateUtil/dateFormat reviewed without a concrete defect; `listMerchantsForAdmin` ILIKE treats `%`/`_` in search as wildcards (low).
